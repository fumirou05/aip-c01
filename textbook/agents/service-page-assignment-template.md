# サービスページ割り当てテンプレート

以下を埋めてサービスページ執筆者、レビュー担当、または昇格サービスページ執筆者へ渡す。

```text
役割: サービスページ執筆者 | サービスページレビュー担当 | 昇格サービスページ執筆者
Page ID:
重要度: A | B | C
対象サービス／機能:
対応Task・Skills:
参照するTask文書:
出力パス:
目次の主要機能サブ目次:
関連literal pages:
関連supplimental pages:
必ず確認する公式URL:
追加で確認すべき変更されやすい事項:
編集してよいファイル:
編集禁止ファイル:
昇格回数: 0 | 1
直前のレビュー報告: （昇格執筆の場合は全文）
完了時に報告する事項:
```

## 執筆者への共通依頼文

```text
textbook/AGENTS.mdとtextbook/agents/service-page-writer.mdに従ってください。
割り当てられたservice-pagesの1ファイルだけを編集してください。
目次の主要機能サブ目次をAWS公式資料で検証し、サービスの役割、管理境界、入力、処理、出力、主要な連携を体系的に説明してください。
Task順の説明や選定シナリオを重複させず、関連するliteral／supplimental pageへリンクしてください。
```

## レビュー担当への共通依頼文

```text
textbook/AGENTS.mdとtextbook/agents/service-page-reviewer.mdに従ってください。
対象ページの執筆完了後にレビューし、割り当てられた1ファイル以外は編集しないでください。
公式根拠、主要機能の体系性、試験範囲、管理境界、既存ページとの役割分離、読みやすさを判定してください。
必ずPASS、FIX、ESCALATEのいずれかを返してください。小さく安全な修正は直接反映してFIXとし、構造的な問題だけをESCALATEとしてください。
```

## 昇格執筆者への共通依頼文

```text
textbook/AGENTS.mdとtextbook/agents/service-page-writer-high.mdに従ってください。
これはレビューでESCALATEとなったサービスページの初回かつ唯一の昇格です。
直前のレビュー報告を作業指示としてAWS公式資料で再検証し、割り当てられた1ファイルだけを修正してください。
指摘の解消に必要な範囲は再構成してよいですが、指摘と無関係な全面改稿は行わないでください。
```
