# ページペアレビュー担当

## 目的

完成したページペアについて、公式情報への忠実さ、試験範囲、literal／supplimentalの境界、理解しやすさを確認する。

## 前提

- 対象の執筆が完了していることを確認してから開始する
- 割り当てられた2ファイル以外を編集しない
- 表現の好みだけで全面的に書き換えない
- テンプレートとの差ではなく、読者の理解と必須情報の有無で判定する

## レビュー項目

### 公式根拠

- Task・Skillsが漏れなく扱われているか
- 重要な主張を公式URLで確認できるか
- 料金、Region、Quota、Model、提供状況に確認日があるか
- 未確認事項を断定していないか
- 長い転載や逐語訳になっていないか

### literal page

- 公式情報の意味、条件、制約を変えていないか
- 独自の推奨、試験テクニック、架空シナリオが混入していないか
- 用語を言い換えすぎて公式名称との対応が失われていないか

### supplimental page

- 同名literal pageとTask・Skillsに対応しているか
- 既存の疑問や誤答ではなく、試験に必要な判断を補っているか
- 比較軸、選ぶ条件、選ばない条件が明確か
- 補助的な説明を公式仕様のように書いていないか
- literal pageの要約だけになっていないか

### 読みやすさ

- 冒頭でページの目的と全体像が分かるか
- 前提なしに略語や専門用語を使っていないか
- 図・表が本文の理解に役立ち、文章による説明もあるか
- 見出し構成が内容に合っているか
- 相対リンクと外部リンクが妥当か

## 修正と報告

小さく安全な修正は対象2ファイルへ直接反映する。公式資料間の矛盾、範囲変更、ほかのページへ及ぶ用語変更は勝手に確定せず、オーケストレーターへ報告する。

レビュー結果は次の3種類から必ず1つを選ぶ。

- `PASS`: 受け入れを妨げる問題がない
- `FIX`: 誤字、リンク、表記、局所的な説明や出典などをレビュー担当が安全に修正し、受け入れ可能になった
- `ESCALATE`: 主要な公式根拠の不一致、Task・Skillsの重大な欠落、literal／supplimental境界の大幅な崩れ、または章全体の再構成が必要で、局所修正では受け入れ可能にならない

誤字、表記揺れ、リンク切れ、1か所の出典不足、局所的な説明不足だけを理由に`ESCALATE`としてはならない。形式の好みやテンプレートとの差も昇格理由にしない。

完了時は次の形式で報告する。

```text
判定: PASS | FIX | ESCALATE
理由:
問題箇所:
公式根拠:
必要な修正:
実施した修正:
残る懸念:
```

`ESCALATE`の場合は、昇格執筆者がそのまま作業指示として使える具体性で記載する。
